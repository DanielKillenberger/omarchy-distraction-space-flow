01

Thesis

scope: business

Installing the plugin is three steps and the middle one is by hand. After this spec, setup writes the Hyprland configuration itself: one Lua file in the user's hypr directory, one marked line in hyprland.lua, loaded through Omarchy's optional-require helper so a removed plugin never breaks the compositor.

The one clarification: this removes the copy step, not the setup step. Setup still runs by hand and still asks for sudo, so the marketplace's standard-installation box stays unticked.

First run writes one file, appends one marked line, records path and digest

A first setup run on a stock Omarchy config writes one Lua file in the user's Hyprland config directory containing the three shipped snippets, appends one marked optional-require line to hyprland.lua, and records the file's path and digest in the state directory.

Architecture

scope: technical
source
three shipped snippets

Workspace rule, bindings, listener autostart. They stay in the repository as what setup reads and what the README links to.

setup writes
one Lua file

In the user's hypr directory, with a header naming the plugin and stating setup owns it. Path and digest recorded in the state directory.

setup appends
one marked line

In hyprland.lua, loading the file through Omarchy's optional-require helper; a marker comment is its identity on rerun and remove.

then
hyprctl reload

New for setup; today only the listener calls hyprctl. Unreachable Hyprland becomes a "reload or re-login" report.

stock config

hyprland.lua loads Omarchy's defaults and carries no plugin lines. Write file, append line, record, reload.

pasted install

Helper path in bindings or autostart, or the workspace rule in hyprland.lua. Write nothing, report where, continue setup. README says: delete the pasted lines, rerun.

unrecognised

Missing or unreadable, loads the module without the marker, or does not load Omarchy's defaults. Untouched, reported, status shows the skipped write.

04

Edge cases

grouped by blast radius
the person's config
  • Temp file and rename for both writes; an interrupted setup never leaves a half-written hyprland.lua.
  • hyprland.lua changes by exactly one appended or removed line, otherwise byte-identical.
  • Setup never parses Lua; it matches the marker line, so surrounding edits survive.
removal and drift
  • Remove with a missing file or line is a no-op for that part and still succeeds; a stale record is dropped.
  • An edited written file is moved to the state backup, never deleted.
  • A config without the optional helper is the unrecognised case, never a crash.
the marketplace
  • 3.0.0 was reviewed on the claim that the plugin does not edit the Hyprland config. The submission notes reverse that claim before the next request, under the already-flagged installer capability.
  • The manifest moves to 3.2.0 in the same pull request; the version check refuses runtime changes under a tagged version.
05

Boundaries

scope: business
this spec is
  • One file written, one marked line appended, both recorded and reversible.
  • Detection of pasted installs with a documented manual step.
  • A reload after the write, with a report when Hyprland is unreachable.
this spec is not
  • Any other change to the person's Hyprland files, including the per-file configs for bindings, autostart, or windows.
  • Migration of a pasted install by deleting lines the person pasted.
  • A change to the bindings, including the Super+Tab takeover; edit the written file instead, and its digest then protects it from remove.
  • A standard install; the marketplace acknowledgment stays unticked.

Decision context

chosen · evidence · rejected
D1 · shape
One file plus one optional-require line.
"can we not include the copy into the setup?"
Rejected appending into the three per-file configs (three owned files, no clean undo); a plain require line (a missing module stops the whole config); an Omarchy plugin hook (none exists).
D2 · pasted installs
Detect and document, never migrate.
Every 3.x install pasted the snippets by hand; the maintainer's own machine is one.
Rejected setup deleting pasted lines from the person's config, a worse failure than asking them once.
D3 · install claim
The copy step goes; the setup step and the sudo prompt stay.
"why didn't we tick the standard installation acknowledgement?"
Rejected ticking the standard-installation box; the plugin still needs manual setup.
