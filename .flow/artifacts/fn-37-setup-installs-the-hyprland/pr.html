The 90-second read

what to verify

Setup now writes the Hyprland configuration itself: one owned Lua file and one marked line in hyprland.lua, loaded through Omarchy's optional-require helper. Ownership is a recorded digest, so a person's edit is never overwritten by a rerun and never deleted by remove.

Three claims carry the PR: setup never writes over a file it did not record and remove never deletes one it did not write; a pasted install is detected across every Lua file in the directory and never doubled; a write that could not happen shows up in status instead of vanishing into one stderr line.

what could bite later
high
Writing into a person's config

Setup now edits a file it does not own. The byte-identity promise rests on writing hyprland.lua last through a temp file with its mode kept; a regression there corrupts a config on every install.

medium
Ownership by digest

Rerun and remove both decide from the recorded digest. A record lost with the state directory turns a shipped-bytes file back into setup's and leaves an edited one alone; that is the designed degradation, and the tests pin it.

medium
Marketplace claim change

The 3.0.0 review accepted a plugin that did not edit ~/.config/hypr. The submission notes now say the opposite; the next verification request lands under the already-flagged installer capability.

low · deferred
